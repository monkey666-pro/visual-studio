# 动态链接库（DLL）

## 什么是 DLL？
- 全称：Dynamic Link Library（动态链接库）。
- 物理形态：在Windows平台上，它是一个以 `.dll` 为后缀的独立文件。
- 通俗理解：它就像一个“功能零件仓库”。我们把写好的代码（比如数据库操作、算法计算）打包进这个仓库，但先不把它们塞进主程序里，等主程序运行需要的时候，再去仓库里调用。

> 💡 核心优势（为什么用DLL）：
>
> 1. 代码复用：多个WinForm程序可以共用这一个DLL文件。
> 2. 模块化：团队分工时，A写界面（WinForm），B写逻辑（DLL），互不干扰。
> 3. 独立更新：如果逻辑出了Bug，只需替换DLL文件，无需重新安装整个WinForm程序。



### DLL 与 WinForm 

#### 创建 DLL 项目（生产零件）
我们通常创建一个“类库（Class Library）”项目/也可以在项目属性中设置为"库类"。

1. 新建项目，选择 “类库 (.NET Framework)” 或 “类库 (.NET Core/.NET 5+)”。
2. 在类库中编写公共类和方法（注意：必须加上 `public` 关键字，否则外部WinForm看不见）。
   ```csharp
   namespace MyTools
   {
       public class Person  // 必须是 public
       {
           public string GetName() => "张三";
       }
   }
   ```



#### 生成 DLL 文件（打包零件）

- 在解决方案资源管理器中，右键点击该类库项目，选择 “生成(U)”。
- 生成成功后，Visual Studio 会在项目的 `bin\Debug` 或 `bin\Release` 文件夹下，自动产生一个 `.dll` 后缀的文件（例如 `MyTools.dll`）。

> 注意:  这个 `.dll` 文件就是我们最终要的“成品零件”。它不依赖 `.exe` 也能独立存在。



#### 在 WinForm 中添加引用（安装零件）

现在我们要把这个零件装进 WinForm 主程序里。有两种常用方式：

- 方式A（项目引用——最常用，开发期推荐）：
  1. 在 WinForm 项目（即你的主程序 `ConsoleApp2`）中，右键点击 “依赖项”。
  2. 选择 “添加项目引用(R)”。
  3. 在弹出的“引用管理器”中，左侧选择 “项目” -> 中间勾选你的 DLL 项目（如 `ConsoleApp1`）-> 点击确定。
    *(这样DLL源码和WinForm在同一个解决方案下，修改DLL代码后重新生成，WinForm自动感知)*

- 方式B（直接引用文件——用于使用别人给的现成DLL）：
  1. 在 WinForm 项目的 “依赖项” 上右键 -> “添加引用”。
  2. 点击左下角的 “浏览(B)” 按钮。
  3. 找到存放在电脑硬盘上的 `.dll` 文件，选中确定。





### 在 WinForm 界面中调用 DLL

完成引用后，就可以在 WinForm 的按钮点击事件等地方使用 DLL 中的功能了。

```csharp
// 1. 先引用命名空间（注意：using 后面是DLL里定义的命名空间）
using MyTools; 

namespace WinFormApp
{
    public partial class Form1 : Form
    {
        private void button1_Click(object sender, EventArgs e)
        {
            // 2. 直接实例化 DLL 中的类并使用其方法
            Person p = new Person();
            MessageBox.Show(p.GetName());
        }
    }
}
```







##  DllImport

> 它是 C# 中的一个声明性特性（Attribute）。它的作用是告诉 .NET 运行时：“我要调用的这个函数不在我的 C# 代码里，而在某个外部的原生 `.dll` 文件中，请帮我去那里找。”

这种技术被称为平台调用

### 语法结构

```csharp
using System;
using System.Runtime.InteropServices;

public class MyClass
{
    // [DllImport("dll文件名")]
    // public static extern 返回类型 函数名(参数类型 参数名);

    [DllImport("User32.dll")] // 指定要加载的DLL名称
    public static extern int MessageBox(IntPtr hWnd, string text, string caption, uint type);
}
```

关键要素解释：

- `[DllImport("User32.dll")]`：指定包含该函数的原生 DLL 名称。如果是系统自带的，写文件名即可；如果是第三方的，通常需要写完整路径。
- `public static extern`：固定写法。`static` 表示无需实例化类即可调用，`extern` 表示该方法的实现体在外部（DLL 中），所以这里只声明，不写大括号 `{}`。
- 返回类型和参数：必须与原生 DLL 中的函数签名严格匹配，否则程序会崩溃或报错。





### 示例：

```C#
using System.Runtime.InteropServices;

namespace WinFormsApp2
{

    internal static class Program
    {
        [DllImport("kernel32.dll")]
        public static extern bool AllocConsole();
        /// <summary>
        ///  The main entry point for the application.
        /// </summary>
        [STAThread]
        static void Main()
        {
            AllocConsole();
            // To customize application configuration such as set high DPI settings or default font,
            // see https://aka.ms/applicationconfiguration.
            ApplicationConfiguration.Initialize();
            Application.Run(new Form1());
           
        }
    }
}
```

` [DllImport("kernel32.dll")]`
`public static extern bool AllocConsole();`

这两行代码声明了一个外部函数，它的作用是：告诉 .NET 运行时，在 kernel32.dll 这个系统动态链接库里，有一个叫 AllocConsole 的 C/C++ 函数，我要在 C# 里调用它。

随后在 `Main` 方法中：调用了这个函数，效果就是——在 WinForms 程序启动时，会额外弹出一个黑色的命令行窗口（控制台）。

> 就是说一旦调用了 `AllocConsole()`，那我们就可以在程序的任何地方（包括 `mainForm` 的按钮点击事件里）写：控制台输出了: 比如 `Console.WriteLine($"用户点击了按钮，当前时间：{DateTime.Now}");`



### 注意事项

1. 千万不要用它加载你自己的 WinForms 控件 DLL：
   - `DllImport` 只能加载导出函数（C语言风格函数）的 DLL。
   - 你编译的 DLL 库是 .NET 托管程序集，不导出标准的 C 函数。想引用它，必须用 “添加引用”（`using` 命名空间，new 对象），而不是 `DllImport`。
